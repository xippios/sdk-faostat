# Upstream documentation snapshot — FAOSTAT

Source of truth for every endpoint wrapper (ADR-0003). The files in this directory are
written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the pages in the
table below and refreshed deliberately by PR, so that changes show up as diffs. This
file is generated by the same script; nothing here is edited by hand.

## Attribution

FAOSTAT's data are governed by the FAO Statistical Database Terms of Use,
https://www.fao.org/contact-us/terms/db-terms-of-use/en/, kept whole as
`pages/db-terms-of-use.md`. Their licence, as printed:

> Unless specified otherwise in their metadata or webpage, all datasets disseminated
> through FAO corporate statistical databases (see examples in Annex 1) are licensed
> under the Creative Commons Attribution-4.0 International licence (CC BY 4.0) available
> here as complemented by the Terms of Use outlined below.

Annex 1 of the terms lists FAOSTAT among those databases. The citation the terms ask
for, as printed:

> FAO. [YYYY (year of last update)]. [Name of database: Name of dataset OR Name of
> database]. [Accessed on [DD Month YYYY]]. [URL] Licence: CC-BY-4.0.

The terms page's footer prints `© FAO 2026`, linked to FAO's Terms and Conditions
regarding the Reuse of Web content, https://www.fao.org/contact-us/terms/en/, which the
terms incorporate by reference (cited, not fetched). The OpenAPI document's `info` names
no licence, terms of service or contact, and the ReDoc page, the portal's shell, the
catalogue and the samples state none.

Every statement of a copyright, a licence or terms of use the pages print is recorded,
as printed, in `ATTRIBUTION` of `scripts/refresh_upstream.py`: the three above, the
terms' name, and the terms page's other sentences and headings that name a licence or

  (“Database terms”) and the Terms and Conditions regarding the Reuse of Web content,
  which are incorporated herein by reference.`

- `Any dispute, controversy or claim arising out of or in relation to this licence that

  Arbitration Rules of the United Nations Commission on International Trade Law

The script stops when a page states one it does not record, or when one it records is no
longer printed. The documentation's text is reproduced here as this package's reference
(ADR-0003); the publisher's objection is met by replacing it with a summary that keeps
the names and semantics the wrappers rely on.

## How this is captured

FAO documents the FAOSTAT API in an OpenAPI document, kept verbatim as
`openapi/faostat_openapi.yaml` from
https://www.fao.org/faostat/en/docs/faostat_openapi.yaml (`SPEC_URL`), and renders it on
the ReDoc page https://www.fao.org/faostat/en/docs/redoc-static.html. No page links the
document: it is served beside the ReDoc page, which embeds a copy of its own and draws
it in the browser. The script checks on every run that the copy holds no text the
document lacks but a development server, and that the page's text is the copy's and
ReDoc's labels; the page is a row without a file.

The developer portal, https://www.fao.org/faostat/en/#developer-portal, is a fragment of
https://www.fao.org/faostat/en/, the portal's application shell, an empty page that a
RequireJS application fills in the browser; it carries no documentation text and is a
row without a file.

The FAO Statistical Database Terms of Use are converted to Markdown with the standard
library's `html.parser`: the page's content, its headings, paragraphs, lists, tables and
links (made absolute) kept, a table with merged cells or a nested table kept as HTML,
the site's header, navigation, breadcrumb, share buttons, footer and scripts dropped.
The run stops on an element the converter does not know.

The bulk downloads' catalogue is open and kept verbatim; its description of the census
dataset WCAD says census reports are “available in the public domain”, which states
nothing about the catalogue, and the script records the phrase as incidental
(`INCIDENTAL`). The four samples under `samples/` are answers of the API, kept verbatim,
fetched with the FAO account's bearer token: the script logs in once with `auth_login`
(`POST /auth/login`, the form fields `username` and `password`, from `FAOSTAT_USERNAME`
and `FAOSTAT_PASSWORD`), after every keyless page, and sends the access token on these
four requests only; neither the credentials nor the token is recorded. Their
`metadata.processing_time` changes on every request, which `--check` disregards. They
are structural samples; test fixtures are recorded separately.

What the API does that the OpenAPI document does not state, observed in probes on
2026-10-29 and not documented (the document lists none of these parameters for
`get_data`; `no_records` and `null_values` appear only under `post_datasize`, `limit`
only under `post_rankings`):

- `page_size` with `page_number`, and `limit` with `offset`, page the data answer
  (`page_size=2&page_number=2` answered rows 3 and 4, `limit=2&offset=0` rows 1 and 2);
  without them the whole answer comes in one body (30,942 rows, 9.3 MB); no maximum page
  size was found (`page_size=60000` answered 60,000 rows).
- `no_records=true` answers `[{"NoRecords": N}]` only, `N` the number of rows, printed
  as a float (`1643610.0`) for a large count.
- The data endpoint takes the options `show_codes`, `show_unit`, `show_flags`,
  `show_notes` and `null_values`, which the portal sends; an answer without them carried
  the same 15 columns.
- `area_cs` and `item_cs` name the coding system of the codes sent: with `area_cs=FAO`
  and `item_cs=FAO` the columns are `Area Code (FAO)` and `Item Code (FAO)`; without
  them the codes are FAO's, under `Area Code` and `Item Code`.
- The element codes a query filters by are not the answer's `Element Code`:
  `element=2510` (Production Quantity, as `codes/element/QCL` lists it) answers rows
  with `Element Code` `5510`, and `element=5510` answers no rows, as any unknown code
  does.
- A data query with no filter is refused with HTTP 500 and the body `Please add at least
  one filter.`; an unknown domain with HTTP 500 `Index: 0, Size: 0`.
- No answer carried an `X-RateLimit-*`, `RateLimit-*` or `Retry-After` header.
- The answers' field names differ from the document's schemas: `groupsanddomains`
  answers `group_code`, `domain_code` and their like, not `GroupCode` and `DomainaCode`;
  the data answer `Area Code` and `Item Code`, not `Area Code (M49)` and `Item Code
  (CPC)`; the samples show them.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Bytes and sha256 are those of the body as fetched: a converted page's row
holds the HTML page's. Last-Modified is the HTTP header in UTC, ETag as sent. A page
recorded without a file is `(no file)`. Requests go one at a time, 2 s apart, identified
as `xippios-faostat refresh_upstream (+https://github.com/xippios)`; a keyless one is
retried at most once, a keyed one never. No API key exists. The four samples are fetched
with the account's bearer token after one login; no other request sends a credential,
and neither the credentials nor the token is written.
